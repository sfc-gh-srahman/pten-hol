01 / Snowflake's view

RAG gives the model your knowledge without retraining it

A large language model answers from a specific, governed knowledge base. Responses stay current, cite their sources and respect who is allowed to see what. For PTEN, the question of how the agent gets drilling domain knowledge is a context repository problem, not a model problem.

CORE 1Client / app UIChat or question answering where users ask in natural language.
CORE 2Context repositorySources aggregated, governed and refreshed, then chunked and embedded.
CORE 3SearchRetrieves the most relevant chunks for the question.
CORE 4LLM inferenceGenerates the answer from the question plus retrieved context.
ENTERPRISEEmbedding modelTurns documents and queries into vectors.
ENTERPRISEData pipelineKeeps the knowledge base continuously up to date.
ENTERPRISEEvaluation + monitoringMeasures answer quality and system performance.
ENTERPRISEGovernanceRestricted content only reaches authorized users.

02 / Shared foundation

Build retrieval once, on Snowflake

Both implementation levels in this lab use the same documents, chunks and Cortex Search service. Cortex Search handles embeddings automatically and combines semantic and keyword search.

DocumentsLab-authored drilling practice samples (S3 or upload)
→
StageExternal stage over S3, the hybrid pattern
→
ParseAI_PARSE_DOCUMENT layout / OCR
→
ChunkChunks table with source metadata
→
Cortex SearchHybrid index, embeddings automated, refreshes with the table
Swap in your own documents: repoint the stage at PTEN's S3 prefix, reload the chunks table and let the Search service refresh. Nothing downstream changes.
